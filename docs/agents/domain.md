# Domain docs

This repository uses a single-context layout: one shared domain vocabulary.

## Before exploring

Read `GLOSSARY.md` at the repository root.
Read relevant architecture decision records (ADRs) under `docs/adr/`.

If these files are absent, proceed silently.
The domain-modeling skill creates them when terms or decisions are resolved.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and test names.
If a necessary concept is missing, note the gap for domain-modeling.

## Decisions

If a proposal conflicts with an ADR, name the ADR and explain the conflict.
Resolve the conflict explicitly before replacing the recorded decision.
